Native and desktop builds now ship tighter defaults for page content, external links, temporary files and installed updates.

- **A content security policy by default.** An Akan app's native build puts a Content-Security-Policy in its `index.html`: scripts from `'self'` only (inline ones by hash), connections to `'self'` and any `https:` or `wss:` origin, `https:` images, media, fonts, stylesheets and frames, inline styles, and the plain-`http:` origins the build knows of (an `http:` `AKAN_PUBLIC_SERVER_URL`, `http://localhost:*` in local mode, the carried server's loopback port). The policy also sets `form-action 'self'`, `base-uri 'self'` and `object-src 'none'`, so a form that posts to another origin (an outside payment page, say) no longer submits, and `<object>`/`<embed>` content does not load; add the origin in a map (`{ "form-action": ["https://pay.example.com"] }`). A directive map in `native.csp` adds sources to that policy (`{ "script-src": ["https://cdn.example.com"] }`), a string replaces it, and `native.csp: false` ships no policy, as before; `native.csp: ""` is a build error. In a map, directive names ignore case, a `default-src` entry is added to every fetch directive of the policy but `object-src`, and a directive the policy lacks starts from the one CSP falls back to (`script-src-elem` from `script-src`, `manifest-src` from `default-src`). akan-native hashes inline scripts and styles into `script-src-elem` and `style-src-elem` too when a policy has them.
- **External links open `https:`, `mailto:` and `tel:` by default.** `opener.openUrl`, and the links and `window.open` calls the iOS, Android and desktop shells hand to the system, open only URLs that the app's `opener` permissions allow: plain `http:` links are not opened unless the app lists them, and an akan-native app whose `capabilities` grant no `opener` hands no link to the system. `native.openUrls` names the URL patterns; `native.openUrls: ["*"]` restores the previous scope. When the app refuses a link this way, `Link` and the router no longer retry it with `window.open`.
- **Private temporary folders on Linux.** `file-picker` copies, the `filesystem` plugin's `temp` folder and `external-view` captures live under `$XDG_CACHE_HOME/<appId>/tmp` (`~/.cache/<appId>/tmp` when unset), in folders only the user can open, instead of `/tmp/<appId>`. Unlike `/tmp`, nothing empties it at a restart: `file-picker` and `external-view` empty their own folders at launch, and a file an app writes to `temp` stays until the app removes it. macOS and Windows keep their per-user temporary folder. Set `XDG_CACHE_HOME` to move it.
- **single-instance on Linux without `XDG_RUNTIME_DIR`.** The socket and lock move into a per-user `akan-native-<uid>` folder that only the user can open, and an existing folder another user owns or others can read is not used. A private `XDG_RUNTIME_DIR` is used as before.
- **A downloaded desktop release is checked again before it is installed.** `updates.apply()` repeats the code-signature check (macOS) and the signer check (Windows) on the staged bundle. The install at quit installs a bundle only once that check passed in this run, outside the time the quit hooks share: as the release was downloaded or the app started, and again when a quit is asked for (Cmd+Q, the last window closed, a logout), which waits up to 10 s for it. A bundle that no longer passes is removed and has to be downloaded again; one whose check has not finished stays for the next quit.
- **`updates.windowsSigners`** (new, Windows): certificate thumbprints a release's executable must be signed by. Unset keeps the existing check that a release is signed by the same certificate as the running app.
- **`updates.expiresIn`** (new): `akan publish-update` signs an `expiresAt` that many seconds ahead (at least 3600) into the release manifest, and desktop, iOS and Android apps refuse a manifest past its `expiresAt`. Unset publishes no expiry, and a manifest without one is accepted as before.
- **`desktop.screenCapture: "auto"` on Windows denies camera and microphone requests**, which the setting would otherwise grant without asking. `"picker"`, the default, keeps the usual prompts.
- **`native.csp`, `native.openUrls`, `updates.windowsSigners` and `updates.expiresIn` are typed in `akan.config.ts`**, and `csp` and `openUrls` given in the `native` section reach the native build, as a target's own did.
- **A release build with `devtools` on prints a warning**, since the web inspector then reaches every plugin the page can call.
- **Paths with a `.` or `..` segment are answered by the app shell** on every platform, literal or percent-encoded, and a navigation to one is not loaded as a page, as `/__akan_native/*` paths already were.
- **A public env value holding a private key is refused** when the native build records its `AKAN_PUBLIC_*` values, as names with `SECRET`, `TOKEN`, `PASSWORD`, `PRIVATE` or `CREDENTIAL` already were.
- **akan-native only warns about `'unsafe-inline'` in `script-src`.** Inline styles under `style-src 'unsafe-inline'` no longer produce a warning; inline scripts are still left unhashed when `script-src` allows them.
