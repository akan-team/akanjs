`AnthropicLlm` keeps Claude's thinking across tool rounds. Claude Opus 5.5 and Sonnet 5.5 think by default, and their `thinking` and `redacted_thinking` blocks used to be dropped from every answer, so the model lost its reasoning each time a tool ran. An answer now carries them, signatures included and in the order the model wrote them, as `providerContent` on `LlmTurnAnswer` and on the assistant `AgentWireMessage`. `agentService.loop` stores it with the message, and the next request replays it verbatim ahead of the calls it came with. The OpenAI dialect ignores it, and a message whose text or calls no longer match the blocks is sent without them. Upgrading needs no step; a host that stores the loop's messages should keep the new field, or a resumed run starts without that reasoning.

Anthropic binds a thinking block to every turn before it. Here those turns change: a turn's context rides only the newest user turn. An account the API holds to that check (per model, accounts created from 2026-08-31) refuses such a request with a 400, and `AnthropicLlm` then asks again with `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` under the `thinking-binding-controls-2026-08-01` beta, and keeps doing so for that model. If that is refused too, it asks once more with no thinking blocks. `AnthropicLlm.requestBody` takes `thinking: "drop" | "strip"` for code that sends the request itself, and `AnthropicLlm.thinkingBindingBeta` names the header value `"drop"` needs.

A `stop_reason: "refusal"` used to read as an ordinary end, with any partial text kept as the answer. It now throws `agent.error.llmDeclined` with `{ provider, category }`, streamed or not, carrying the tokens it cost. Anthropic answers a decline with a 200, and its partial output is to be discarded. `LlmOverflow.declined(host, category, explanation)` builds the error for an app's own adaptor, and the explanation goes to the server log only. `AnthropicLlm.turnAnswer` takes the host as an optional second argument, for the error to name.
