MCP Apps v2: the unit of an MCP App is now one component, `page().app()`, instead of a whole `.prompt()` screen.

- **Tools.** Each `.app()` is a tool named after the app. Its input is the page's `.param()` and `.search()`. Its annotations are `readOnlyHint: true, openWorldHint: false`, since the load may only query. Its `_meta.ui.resourceUri` is `ui://<app>/apps/<name>`. A call checks the arguments, runs the route guards, and then runs the app's load alone: no layout body and no `.render()`. The model receives the briefing of what the load fetched plus `Open the full screen: <page URL>`. A view receives the raw values in `_meta`, and the route values it starts from in `structuredContent`.
- **`.prompt()` is a briefing again.** It stays a prompt and a text tool, with `readOnlyHint: false`, since its run renders the whole page. It no longer names a view.
- **Names.** Prompts and apps share one namespace. Two pages that claim one name fail the listing, whatever the kind of each claim. An endpoint keeps its name over an app's, with a warning at boot, as it already did over a prompt's. `prompts/get` serves only prompts.
- **Read-only deployments** (`option.setMcp({ readOnly: true })`) keep the app tools, their resources and the views. A prompt's text tool is left out, since its run may write; the prompt itself stays. An app result there carries `_meta["akanjs/readOnly"]`.
- **Resources.** Each app has its own `ui://<app>/apps/<name>` view, read from the `mcp-apps/` folder that the build writes beside `csr/`. The basePath shells (`ui://<app>/app[/<basePath>]`) are gone.
- The server speaks the modern MCP revision over `server/discover` once the listed pages declare no `.app()`, instead of no `.prompt()`.
- **The view boots without a router.** `McpAppBoot.run({ app, page, root, rootOverrides, overrides, basePath })` (`akanjs/webkit`) runs the app's load again with the route values from the result, in the host's language when the app speaks it. Its first reads come from the snapshot. It draws the element inside the `_overrides.tsx` over the page and the generated root layout's new `McpAppRoot`, which renders `System.App` (`akanjs/ui`): the root layout's theme, fonts and providers, with no frame, router or socket. The overrides the web draws outside the root layout (on its folder, or on a folder above it that holds no layout of its own) wrap `McpAppRoot` instead, so its toasts and approvals take them too. No layout body or `.render()` runs in a view.
- **A view never moves.** `csrLocation` reads the screen the view draws rather than the host's sandbox address (`csrLocation.view(href)`), so `usePage()`, a `<Link>` and the agent's context name that screen. A link or `router.push` to one of the app's screens opens that screen's web page through the host, under the page's basePath. A fragment of the view's own screen scrolls the view to its target, found as written or percent-decoded as a browser finds it, and `router.back()` and `router.refresh()` do nothing.
- **Failures and language.** A read that fails while the element draws shows "The page failed to load.", as a failed load does, instead of an empty frame. The view sets `<html lang>` to the language it draws in.
- **Writes in a read-only deployment.** The view's fetch bridge refuses a mutation before it reaches the host, with `base.error.readOnlyDeployment` ("This server is read-only, so {endpoint} cannot run here."). The person sees it as a toast in their own language, and a host model that presses the same button reads it as a tool error. A write would otherwise reach a host that lists no write and answers "Unknown tool".

Upgrade note: a `.prompt()` page is no longer drawn in an MCP Apps host. Declare `.app()` on the page for each component the host should draw. The v1 view machinery is gone: `hiddenLayoutContext` and `useInHiddenLayout` (`akanjs/client`), the memory mode of `csrLocation` (`useMemory`, `isMemory`), and `RenderLayer`'s `isEmbedded`. With them goes the view-only behaviour of hiding layout chrome and dropping the navbar's back button on the first screen.
