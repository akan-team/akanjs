A server-rendered page now shows its content as soon as the HTML arrives. The response started before the layout and page bodies had rendered, so React put even a page whose data was ready into a hidden segment and revealed it with a script it throttles to 300ms after the first paint. A browser test that clicked in that gap failed now and then, and a URL with a fragment (`/pokemon/pikachu#moves`) missed its target. `ssr: "block"` did not fully help: React still showed the `.loading()` fallback in front of a large page it had already rendered.

- **The response waits for the levels above the first `.loading()`.** Every layout and page above a route's first `.loading()`, or the whole route when it declares none, renders before the first byte is sent and is written in place, with the client modules it uses loaded. Each level keeps its own boundary, so a client component that fails on the server, or a hydration mismatch, still client-renders only its level. A level with `.loading()` sends its fallback first and reveals its content together with the levels below it. A route whose data is slow and that declares no `.loading()` now sends nothing until the data is ready; give the slow level a `.loading()` to keep the fallback first. An async component a body renders that is still pending once the bodies are done streams in after the shell, as before. A client navigation's payload starts at the same point.
- **Real statuses from the page body.** A `router.notFound()` or `router.redirect()` raised after I/O by a body above the first `.loading()` is a real 404 or 3xx. An error such a body throws after I/O answers with the nearest layout's `.error()` view and status 500, or the error page when none declares one. Before, the server sent a 200 page with that level empty, and the same error broke the page again when the browser rendered it.
- **`ssr: "block"` writes every boundary in place,** so a blocking page never shows its `.loading()` fallback.
- **Fragments land on their target.** A document opened at a fragment scrolls to the target when React reveals it, if the target was not on the page yet and the visitor has not scrolled; a reload or a back/forward visit keeps the offset the browser restored. A client navigation to another page's fragment lands on the target instead of the top.
