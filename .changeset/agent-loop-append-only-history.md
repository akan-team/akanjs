`agentService.loop` now sends each round a history that only grows, so a provider's prompt cache and Anthropic's check of the thinking it kept both read the next round as the same conversation. Before this change, three things edited earlier turns every round: the run's `context` moved to the newest user turn, opening a toolkit changed the tool list and `openToolkit`'s description, and `findTools` came and went.

- The run's `context` is stored as a user message marked `context: true`, at the point where it was first sent. It is stored again only once it changes, or after a compaction has dropped it. It reaches `onMessage` like any other message, so a host that stores the transcript keeps it. A host that draws the transcript should skip `context` messages, as it skips `summary` ones: they hold the app's data, not the member's words. A marked (`untrusted`) block's message is stored with `tainted: true`. A compaction digest leaves context messages out. The OpenAI dialect joins a context message to the user message beside it. A custom adaptor that sends `messages` as they are sends it as one more user message.
- `openToolkit`'s description and its `name` enum list every toolkit, open or not, and read the same on every round. `findTools` is listed on every round of a run with `search`.
- A run with `toolkits` stores `listed`, the tool names that round showed, on each assistant message. Each `LlmTurnRequest` now also carries `deferred`: the toolkits' tools that are not listed yet. `tools` is still exactly what the round lists, so a custom adaptor that ignores the two fields behaves as before. `AnthropicLlm` declares the deferred tools from round one with `defer_loading: true`, under the `mid-conversation-tool-changes-2026-07-01` beta (`AnthropicTools.beta`). It replays each stored listing before the answer it applied to, as `tool_addition` and `tool_removal` in a system message. Opening a kit therefore leaves the earlier turns, and their thinking, as they were sent. A model that refuses the form (Claude Sonnet 5 and older, Microsoft Foundry) is asked again with the listed tools alone, and from then on gets only those. A request with no deferred tools and no stored listing is sent exactly as before, without the beta header. `AnthropicLlm.requestBody` takes `toolChanges: false` to send the listed tools alone.
- After a history refusal, `drop_block` is now kept for that conversation, keyed by its first signed thinking block, rather than for the whole model. Up to 500 conversations are remembered.

Upgrading needs no step. Store `context` messages and `listed` with the rest of the transcript, or a resumed run sends that context again, and an Anthropic run replays no tool changes for the rounds before it.
