The client now merges a model's slices the way the server mounts them. When an app's slice extends a lib's, the app's guards, `mcp` map, person-only map and `crud` map replace the lib's whole. Before, the client filled each guard list in field by field. A verb the app writes as `None` used to reach the client as undeclared, so the client used the lib's guards and showed a callable `createX` that the server answers with 403. That verb is now sent as `["None"]`, and no client registers a callable `createX` for it. A tab-wide client that applied the lib's signal first also drops the handlers it had registered for that verb. The app's slice also holds when a tab or a rendering server evaluates the lib's client bundle after the app's: the lib's own signal no longer brings back the lib's guards, maps or handlers. A list that names a real guard next to `None` still mounts, as it does on the server. A fetch client created after another in the same process, such as a lib's on the server, now also finds the endpoints the earlier one registered, where before it saw only its own.

An app slice that writes no `mcp` map now inherits every verb the lib's slice took off the shelf, including a root `mcp: false`. **Operators:** an app that extends a `libs/shared` model whose slice says `mcp: { cru: false }` (such as `admin` or `notification`) and writes no `mcp` map of its own stops publishing those generated writes on `/mcp`. Write `mcp: { cru: true }` on the app's slice to publish them again. HTTP is unchanged.

`option.setMcp()` takes `excludeSignals` and `excludeEndpoints`. They keep a whole signal, or single entries (generated ones included), off `/mcp`'s `tools/list`, `tools/call` and views, while HTTP still serves them. The lists from every lib and the app add up instead of replacing each other. The boot log reports each exclusion the way it reports `mcp: false`, and warns about a name that matches nothing served.

`akanjs/test` exports `getServedMcpCatalogue({ as, ui })`. It returns the tools and prompts the running test server's `/mcp` lists a guest, or the account of a test agent or fetch client passed as `as`, across every page, with `findTool`, `undescribed` and `listingCost`. By default it is the listing a client that draws no MCP Apps views receives, which is what most clients see. `ui: true` gives the listing a client drawing those views receives: on a server that serves views, it adds the entries published only to a view (`visibility: ["app"]`), and elsewhere it is the same listing. It runs the router's own `tools/list` handling in-process, through the same registry, `setMcp` options and account-guard filter, so a test needs no OAuth token. `TestServer#servedMcpCatalogue` does the same for a server you start yourself.
