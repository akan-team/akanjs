Signals, websocket rooms, MCP, OAuth and the agent relay now take the narrower default wherever the old one let a caller reach more than the endpoint declared. Each changed default has a way back:

- An endpoint, slice query or pubsub room that declares no guards is refused with 403. `[Public]` is how an endpoint is opened to anonymous callers. Outside local operation (an operation mode other than `local`, and not under `bun test`), a server whose signals declare a guardless endpoint stops at boot and names each one; under local operation it warns. `AKAN_UNGUARDED_ENDPOINTS=open` answers them as before and only warns at boot.
- A slice whose `guards` leaves out `root` mounts no root list or insight, as a CRUD verb left out mounts no endpoint; `root: []` is still refused. Before, the root list and insight answered anyone. Name `root` (`Public` for anonymous callers) to keep them.
- `guard(name)` returns a guard whose `canPass` refuses until the subclass overrides it. Previously it admitted every caller. A guard meant to admit everyone overrides `canPass` to return `true`, or the endpoint uses `Public`.
- A websocket room id escapes every character outside `[A-Za-z0-9_.]` in its arguments, so two argument lists never share a room. `Any` arguments are keyed by their canonical JSON. A live slice's room also carries a digest of its query and internal arguments, so subscribers whose queries differ never share a room. The subscribe ack still echoes the client's own label as `requestRoomId`, so 3.x clients route frames as before. Ids made only of letters, digits, `_` and `.` (ObjectIds) are unchanged. Ids containing `-`, such as UUIDs, and object arguments map to new room ids. During a rolling deploy, a publish from an old instance does not reach a subscriber held by a new one until every instance runs this version.
- An HTTP mutation reads its body only after the account-scoped guards admit the caller. Middleware and account guards still see its path and query arguments, but a body argument is `undefined` until then. The upload does not count against the endpoint's `timeout`.
- A multipart field named `__proto__` is stored as a plain key. A JSON body that is not an object, or is not valid JSON, is answered 400 instead of 500.
- A 500 response includes the error message and stack only under `akan start`, with `NODE_ENV` set to `development` or `test`, or with `AKAN_ERROR_DETAIL=1`. A server whose `NODE_ENV` is unset or unrecognised now hides them. `AKAN_ERROR_DETAIL=1` shows them again.
- The agent relay refuses a request past fixed limits with `agent.error.requestRefused` (413). The limits are 5,000 messages, 512 tools, 256 context entries, 8,000,000 characters of text and 64 MiB of attachment content, set in `AgentRelayPolicy.defaultLimits`. Before, it relayed the request as written. A policy set with `setAgentRequestPolicy` replaces the limits. `AgentRelayPolicy.capped(request, limits)` keeps them inside an app's own policy, and `setAgentRequestPolicy((request) => request)` relays every request unchanged.
- With a quota hook set, one signed-in caller's agent turns run one at a time, and each checks the quota only after the turn ahead has reported its usage. `AgentMeter.use({ serial: false })` lets them run side by side again.
- When an agent turn fails with an error that is not an `Err` after its stream has opened, the stream carries a generic message unless error details are on. The server log keeps the real error. An `Err` still reaches the browser with its key and data.
- Without `auth.verify`, MCP rate-limits a caller that sends a bearer token by its address, as it already did for a caller without one. A token's own id starts a separate budget only once `verify` has accepted the token. `tools/list`, `resources/list`, `resources/templates/list` and `prompts/list` now count against the same budget as calls. `listFor` does not count. To widen the budget, raise `rateLimit.calls`. `rateLimit: false` turns the limit off.
- A browser request to `/mcp` whose Origin matches its own host passes only when that host is an IP address, `localhost`, a host the app declares (`akan.config` domains, `AKAN_ALLOWED_HOSTS`) or the host of a pinned `auth.resource`. If `auth.resource` is not pinned, a token's `aud` is matched only against such a host. To admit another host, list its origin in `allowedOrigins`, add it to `AKAN_ALLOWED_HOSTS`, or pin `auth.resource`.
- The fetch of a client ID metadata document stops reading once the body passes 64 KiB, whether or not it states a length. The document's `grant_types` are narrowed to `authorization_code` and `refresh_token`.
- Dynamic client registration accepts at most 10 `redirect_uris` of at most 2,048 characters each. `OAuthRegistration.maxRedirectUris` and `OAuthRegistration.maxRedirectUriLength` raise either limit.
