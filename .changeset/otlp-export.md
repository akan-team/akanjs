A server can send its spans and log lines to an OpenTelemetry collector over OTLP/HTTP, with no package to add. Nothing is exported until an endpoint is set.

- **The settings are OpenTelemetry's.** `OTEL_EXPORTER_OTLP_ENDPOINT` is a base that `/v1/traces` and `/v1/logs` are appended to; `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` are full URLs. `OTEL_EXPORTER_OTLP_HEADERS` (and its `_TRACES_` / `_LOGS_` forms) holds credentials, which are never logged. `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` name the service. `OTEL_TRACES_SAMPLER` takes `always_on`, `always_off`, `traceidratio` and their `parentbased_` forms, with `OTEL_TRACES_SAMPLER_ARG` as the ratio; the default is `parentbased_always_on`, and any other value is logged once and exports no spans. `OTEL_TRACES_EXPORTER=none` or `OTEL_LOGS_EXPORTER=none` turns one signal off, `OTEL_EXPORTER_OTLP_TIMEOUT` and the `OTEL_BSP_*` / `OTEL_BLRP_*` batch settings work as in the spec, and `OTEL_SDK_DISABLED=true` turns it all off. With no endpoint set, nothing is created.
- **One sampling decision per request.** The first process to take a request over TCP, the gateway or a replica running without one, decides, and the sampled flag of `traceparent` carries the decision to the replica and on to the RSC worker, so a trace arrives whole or not at all. A caller's flag counts only when `AKAN_TRACE_ADOPT` trusts the caller. A queued job decides for itself and links the trace that enqueued it.
- **Each process sends its own**, marked with `akan.process.role` and `akan.replica.index`. The gateway sends a server span per proxied request, named by its method. A replica sends a server span named by the route pattern it matched, a span per endpoint call and a client span per database call. The RSC worker sends its page span as a child of the replica's. Attributes carry the method, the route pattern, the status and the error type, never a URL with its query, a header value, SQL text or a user id, and a failure's exception event carries its error code, not its message.
- **Log records are exported whenever a logs endpoint resolves**, the generic one included. Each carries its trace and span id when written inside a request; attrs that name a secret are redacted before export, as before any other sink. The floor is the console level the process started with.
- **The exporter stays out of a request's way.** Each signal has a bounded queue that sends by size and on a timer, with at most two requests in flight. A full queue drops its oldest item and counts it. 429, 502, 503, 504 and an unreachable collector are retried with backoff until the timeout; any other status drops the batch. A failing collector is reported at most once a minute, by host. The exporter's own requests are not traced. On the way out each process, the RSC worker included, sends what is queued once, for at most 1.5 s.
- A sampled call records its spans as it would under `AKAN_TRACE=1`, so its request line carries `db` and `dbMs`, but it does not join the `AKAN_TRACE` metrics. `SignalTrace.exported` says whether a call was sampled for export. The `x-akan-debug` header does not change what is sampled.
- Bodies are JSON. `http/protobuf` still sends JSON, with a warning; `grpc` and compression are not supported.

**Upgrading.** Nothing changes until an `OTEL_EXPORTER_OTLP_*ENDPOINT` is set. A deployment whose environment already sets one for some other tool starts exporting on upgrade: point it at a collector that accepts OTLP/HTTP JSON, or set `OTEL_SDK_DISABLED=true` for the app. With only `OTEL_EXPORTER_OTLP_ENDPOINT` set, log records are exported as well as spans; set `OTEL_LOGS_EXPORTER=none` to send spans alone. A collector that accepts only protobuf does not work; the OpenTelemetry Collector's `otlp` receiver accepts both.
