An app hands the errors its users hit to an error tracker of its choice with `option.setErrorReporter`, and with `option.setClientReport` the errors their browsers hit too.

- **`option.setErrorReporter((error, context) => …)`** gets each server 5xx, render error, uncaught exception and unhandled rejection as a real `Error` with its `cause` chain. A 4xx never reaches it. `context` is `{ source, traceId, endpoint, routeId, accountId, digest }`: `source` is `server`, `render`, `process` or `client`, `traceId` the request id the response named as `x-request-id`, `endpoint` the `<type>:<key>` that answered, and `routeId` the route pattern, never the URL. `accountId` is set on a `server` report whose request was signed in, and null on the others. A thrown value that is no `Error` arrives as one, with the value as its `cause`.
- **Each error is reported once, after the response, and a bounded number a minute.** The reporter runs off the request; one that throws or rejects is logged once and changes nothing else. One server process hands it at most 600 errors a minute, at most 10 of them uncaught exceptions and unhandled rejections, and at most 3 render errors of one request; it logs one line when it starts skipping. Await what the reporter sends: a send it does not await, failing, comes back as an unhandled rejection of the process and counts toward those 10. Before a crashed process exits, it waits up to 2 seconds for the reporter.
- **It runs in the server that answers**, the solo server or each replica. A render error in the RSC worker reaches the replica's reporter with its digest, route pattern and request id, and its cause chain to five levels. So does an error a client component raises while the server renders the page's HTML, and a page the server answers 5xx for because its worker stopped, timed out or refused. The gateway loads no `option.ts` and reports nothing. A page a full render queue turns away (`AKAN_RSC_WORKER_MAX_CONCURRENCY`) is not reported: `akan_rsc_render_refusals_total` counts it.
- **One fault can arrive more than once, with one `traceId`.** An endpoint that answers 5xx while a page renders arrives as `server` and as `render`; a server error streamed into a page arrives as `render` and, when the browser re-renders that part, as a `client` report of kind `recoverable`. Group by `traceId`.
- **`option.setClientReport({ sampleRate, perAddress, perServer })`**, off unless set, opens `/_akan/client-report` and makes each page view its sample draws send what its browser hit: a React root's uncaught, caught and recoverable errors, `window.onerror` and unhandled rejections, at most five a page view. The reporter gets each as a `BrowserError` (`akanjs/signal`) with `source: "client"` and the page view's request id; its `data` holds the kind, name, message, stack, route pattern, digest, the server's build id and the user agent. Defaults: every page view, 10 requests a minute per address (an IPv6 address counts as its /64) and 120 reports a minute per server process.
- **A report is taken only with the id its page view was given.** The page's `Server-Timing` header carries the request id with a signature over it and the half hour it was issued in, and only on a page no shared cache reuses: the default `no-cache` and a signed-in page's `private, no-cache` carry it, a `public` or switched-off `AKAN_HTML_CACHE_CONTROL` does not. The server takes that id for 30 to 60 minutes and five times. The page reads it once, when the document loads, so a report after an in-app navigation carries the first document's id with the current route pattern.
- **Which servers take a report.** The signing key comes from `AKAN_LOG_DEBUG_HEADER` when it is 32 characters or more, with the app name and environment, so every server of a deployment that sets it takes an id any of them gave. Without it, the replicas behind one gateway share a key the gateway makes at start, and a server run alone uses its own: reports are then taken only behind the gateway, or by the process, that served the page. Set the secret when more than one gateway or pod answers for the app.
- **What a page sends, and what the server keeps.** A report carries no cookies and no referrer. In its name, message and stack, a URL or a path loses its query string and fragment, an email address becomes `[email]`, a `Bearer …` value and a JWT become `[redacted]`, and the characters that reorder how a line displays are removed, in the page before it sends and on the server again; the server also removes terminal escapes and control characters and cuts the name, message, stack and user agent to 100, 1,000, 4,000 and 300 characters. The server keeps only a `text/plain` POST from the app's own origin, of 8 KB or less, with a signed id, within the limits; only such a report counts toward `perServer`. Every request, kept or not, is answered with the same empty 204, and the one log line a kept report writes holds only the cleaned values. The code that sends loads on a page's first error, so a page without errors downloads only the listeners, about 430 bytes compressed.
- **What the limits leave.** Each server process counts on its own, so N replicas take up to N times `perServer` and five reports per id each; visitors behind one address share its `perAddress`; and `perServer` is one budget for everyone who loaded a page, past which a minute's later reports are dropped, never queued. The cleaning knows a few shapes, not meanings: keep personal data out of error messages.
- New exports: `ClientReportSetting` from `akanjs/server`, and `BrowserError`, `BrowserErrorData`, `BrowserErrorKind`, `ErrorReporter`, `ErrorReportContext` and `ErrorReportSource` from `akanjs/signal`. The Error Handling cheatsheet has a Report Errors section, the server reference lists both options, and the runtime guideline names them.

**Upgrading.** Nothing changes until an app calls one of the options. An app that forwarded errors through a `Logger.addSink` that parsed error lines can move to `setErrorReporter`, which gets the `Error` itself; keep the sink only for lines that are not errors. A lib may set either option; the app's call wins, `setErrorReporter(null)` clears a lib's reporter and `setClientReport(false)` turns a lib's reports off. A page whose `AKAN_HTML_CACHE_CONTROL` is `public, …` sends no browser reports; pages that should send them keep `no-cache`. An app served by more than one gateway or pod sets `AKAN_LOG_DEBUG_HEADER` to 32 characters or more, the same value on each, before it turns `setClientReport` on.
