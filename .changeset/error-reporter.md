An app hands the errors its users hit to an error tracker of its choice with `option.setErrorReporter`, and with `option.setClientReport` the errors their browsers hit too.

- **`option.setErrorReporter((error, context) => …)`** gets each server 5xx, render error, uncaught exception and unhandled rejection as a real `Error` with its `cause` chain. A 4xx never reaches it. `context` is `{ source, traceId, endpoint, routeId, accountId, digest }`: `source` is `server`, `render`, `process` or `client`, `traceId` the request id the response named as `x-request-id`, `endpoint` the `<type>:<key>` that answered, and `routeId` the route pattern, never the URL. A thrown value that is no `Error` arrives as one, with the value as its `cause`.
- **Each error is reported once, after the response.** The reporter runs off the request; one that throws or rejects is logged once and changes nothing else. Before a crashed process exits, it waits up to 2 seconds for the reporter.
- **It runs in the server that answers**, the solo server or each replica. A render error in the RSC worker reaches the replica's reporter with its digest, route pattern, request id and account id, and its cause chain to five levels. The gateway loads no `option.ts` and reports nothing.
- **`option.setClientReport({ sampleRate, perAddress, perServer })`**, off unless set, opens `/_akan/client-report` and makes each page view its sample draws send what its browser hit: a React root's uncaught, caught and recoverable errors, `window.onerror` and unhandled rejections, at most five a page view. The reporter gets each as a `BrowserError` (`akanjs/signal`) with `source: "client"` and the page view's request id; its `data` holds the kind, name, message, stack, route pattern, digest, the server's build id and the user agent. Defaults: every page view, 10 reports a minute per address and 120 per server process.
- **What a page sends.** The page view's request id rides the page's `Server-Timing` header, and only on a page no shared cache reuses: the default `no-cache` and a signed-in page's `private, no-cache` carry it, a `public` or switched-off `AKAN_HTML_CACHE_CONTROL` does not. A report carries no cookies, no referrer and no URL query string. The code that sends it loads on a page's first error, so a page without errors downloads only the listeners, about 430 bytes compressed.
- **What the server keeps.** Only a `text/plain` POST from the app's own origin, of 8 KB or less, within the limits, naming a request id its sample drew. The name, message, stack and user agent are cut to 100, 1,000, 4,000 and 300 characters, terminal escapes and control characters are removed, and a URL in the stack loses its query string and fragment. Every report, kept or not, is answered with the same empty 204, and the one log line a kept report writes holds only these cleaned values.
- New exports: `ClientReportSetting` from `akanjs/server`, and `BrowserError`, `BrowserErrorData`, `BrowserErrorKind`, `ErrorReporter`, `ErrorReportContext` and `ErrorReportSource` from `akanjs/signal`.

**Upgrading.** Nothing changes until an app calls one of the options. An app that forwarded errors through a `Logger.addSink` that parsed error lines can move to `setErrorReporter`, which gets the `Error` itself; keep the sink only for lines that are not errors. A lib may set either option; the app's call wins, `setErrorReporter(null)` clears a lib's reporter and `setClientReport(false)` turns a lib's reports off. A page whose `AKAN_HTML_CACHE_CONTROL` is `public, …` sends no browser reports; pages that should send them keep `no-cache`.
