Every HTML response now enforces a `script-src` in its `Content-Security-Policy` that names each script the framework writes, so the browser refuses any other inline script, and the framework receives the browser's reports at `/_akan/csp-report`.

- A server-rendered page sends `frame-ancestors 'self'; base-uri 'self'; script-src 'self' 'nonce-…' 'sha256-…' 'strict-dynamic' 'wasm-unsafe-eval'; report-uri /_akan/csp-report; report-to akan-csp` and `Reporting-Endpoints: akan-csp="/_akan/csp-report"`. The hashes name the document's bootstrap script, its flush call and the build's import map, and the nonce the scripts React writes to reveal a streamed boundary. A page replayed from the HTML cache carries no nonce and lists the hash of each of those scripts instead; a response names at most 32 hashes, which keeps the header under 2 KB (a proxy in front reads a response's headers into one buffer, 4 KB in nginx unless configured), so a page whose replay would need more is rendered each time, answers `X-Akan-Cache: BYPASS` with `X-Akan-Cache-Reason: script-hashes`, counts under that reason in `akan_route_cache_lookups_total` and is warned about once per route. `'wasm-unsafe-eval'` lets a page compile WebAssembly; `akan start` adds `'unsafe-eval'` and runs its dev scripts under the nonce.
- The document's per-request values (route state, dictionary URL, import map key, API and WebSocket prefixes) and its Flight chunks are `<script type="application/json">` blocks that the static bootstrap script reads, where they used to be script text. The bootstrap script is at the start of `<head>`, and the client entry module is added by that script once the document ends, where it used to be a `<script type="module">` tag. The client removes these head tags before it hydrates, so React no longer takes a `.head()`'s own `<script>` for one of them, which drew a hydration warning in development.
- The CSR document, the system pages, Akan Studio, the gateway's status page and the OAuth error page send the policy too, each naming its own script by hash. The OAuth error page now also carries the headers every other HTML page has (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`).
- `scriptHashes("sha256-…")` and `scriptNonce()` from `akanjs/client` let a `.head()` name its own inline script: by hash for a constant snippet, which keeps the page cacheable, or by the response's nonce, which makes the page dynamic. Hashes a page declares past the 32 a response names are left out, with one warning per route.
- `/_akan/csp-report` takes what Chromium, Firefox and WebKit post (`application/csp-report` and the Reporting API's `application/reports+json`), up to 32 KB, and logs one `[ScriptPolicy]` warning per route, directive and blocked source, up to 512 kinds a process, with URLs cut to origin and path and control characters escaped. It answers every post with the same empty 204.
- `AKAN_CONTENT_SECURITY_POLICY_REPORT_ONLY=on` sends the script policy as `Content-Security-Policy-Report-Only` instead, so the browser reports and runs what it would refuse; any other value is sent as a report-only header of its own, as written, and unset or `off` sends none. `AKAN_CONTENT_SECURITY_POLICY_SCRIPT_SRC` sets the sources that end `script-src`, in place of `'wasm-unsafe-eval'` (`off` adds none). `AKAN_CONTENT_SECURITY_POLICY_REPORT_URI` points the reports elsewhere, and `off` asks for none. `AKAN_CONTENT_SECURITY_POLICY` still replaces the whole enforced policy as written (`off` drops it); the script policy then only reports.
- `McpAppHost` takes the view's document as `html` and hands it to a frame at `McpAppHost.framePath` (`/_akan/app-frame`), a document that sandboxes itself and that only the app's own pages may frame. A `srcdoc` frame keeps its parent's policy, so a page's script policy refused every script of a view drawn that way; `libs/shared`'s `Remote.Zone.View` draws a connected server's app view this way now.
- `Signal.Doc`'s base URL is drawn once hydrated: the server named the address it was configured with and the browser the page's own, which failed hydration (React error #418) wherever the two differ.

**Upgrading.** Load your pages with the browser console open, or deploy once with `AKAN_CONTENT_SECURITY_POLICY_REPORT_ONLY=on` and read the `[ScriptPolicy]` warnings in the server log until no new one comes. For each refused inline script of your own, either call `scriptHashes()` in that page's or layout's `.head()` with the hash the console error prints, or pass `nonce={scriptNonce()}` to the `<script>`; a `<script src>` written in JSX needs the nonce. Move an `onclick="…"` attribute or a `javascript:` URL into a component's handler. A page that compiles WebAssembly needs nothing, but an `AKAN_CONTENT_SECURITY_POLICY_SCRIPT_SRC` you set replaces `'wasm-unsafe-eval'`: add it to the value. A frame of your own that draws another server's HTML through `srcdoc` with scripts needs the frame route, as `Remote.Zone.View` uses it. In the page source, the route state, the dictionary URL and each Flight chunk are now `<script type="application/json">` blocks, and the markup has no `<script type="module">` tag for the client entry: code or a test that read `self.__RSC_PUSH__(…)` text or looked for that tag finds neither. Because the bootstrap script adds the entry module, `DOMContentLoaded` and `load` no longer wait for it and can fire before any client code runs (on a cached docs page, `load` at 31 ms and the entry at 63 ms). A `load` or `DOMContentLoaded` listener that client code adds without checking `document.readyState` may never be called:

```ts
if (document.readyState === "complete") onLoad();
else window.addEventListener("load", onLoad, { once: true });
```

(`document.readyState !== "loading"` for `DOMContentLoaded`.) A browser test that clicks or types as soon as navigation reports `load` can meet a page that has not hydrated: wait for something only the hydrated page does, such as the result of the action under a retrying assertion or a marker a client component sets in an effect, instead of `load`. A proxy or CDN that sets its own `Content-Security-Policy` adds a policy the browser enforces beside the app's, so it must allow the app's scripts too, or leave the header to the app.
