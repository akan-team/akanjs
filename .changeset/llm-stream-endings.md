The OpenAI-dialect and Anthropic adaptors read more of how a stream ends.

- A stream that closes on its end marker alone (`[DONE]`, or Anthropic's `message_stop`) with no finish reason, after a tool call whose arguments never arrived, now ends as `length` instead of running that call with `{}`. A tool that takes no arguments still runs: one with no `parameters`, or an object schema with no `properties` and no `$ref`, `anyOf`, `oneOf`, `allOf`, `patternProperties`, `required` entry or open `additionalProperties`, any of which may describe arguments. `OpenaiDialect.consumeStream` and `AnthropicLlm.consumeStream` take the turn's tools as a fourth argument to tell the two apart; called without them, every such call counts as cut.
- Tool-call arguments that are not one JSON object, in an answer the model finished, no longer end the turn as `length` with a "ran out of room" message. The model finished it when the finish reason is `tool_calls` or `stop`, or Anthropic's `tool_use` or `end_turn`. The call gets `argsError` (and `args: {}`), and `agentService.loop` answers it with that parse error and the code `invalidArgument` instead of running it, so the model can write it again. The loop stores that answer before anything else in the batch runs or parks, so the refusal is in the transcript as a result. Behind any other finish reason (`length`, `max_tokens`, `content_filter`) or none, the arguments were cut mid-way and the turn is still `length`; a whole (non-streamed) OpenAI-dialect answer follows the same rule, where it used to run such a call with `{}`. The in-page relay has no way to hand a call its error, so it still ends a turn with a malformed call as `length`.
- vLLM's bare `{"object":"error", ...}` frame and a `finish_reason` of `"error"` (OpenRouter's, for an upstream that failed mid-answer) now fail the turn as `agent.error.llmRequestFailed`, or `contextOverflow` when the message says the prompt did not fit, instead of reading as an empty or truncated answer. The failure carries the provider's counts, or an estimate of what was streamed.
- An error inside a stream keeps the status its type names in `agent.error.llmRequestFailed`'s `status`, where Anthropic's always read 500: `overloaded_error` is 529, `rate_limit_error` 429, `invalid_request_error` 400, and so on. An OpenAI-dialect error frame with no numeric code is read the same way from its `code` or `type` (`rate_limit_exceeded` is 429). A type no table names is still 500.

**Upgrading.** Code that calls `agentService.runTurn`, an adaptor's `chat` or a `consumeStream` itself, and runs the tool calls it gets back, must check `argsError` before running a call. An answer the model finished with arguments that do not parse used to stop as `length`; it now stops as `toolUse` with `args: {}` on that call, and a caller that ignores `argsError` would run it with no arguments. Answer such a call with its `argsError` as the error instead. `agentService.loop` and the in-page relay already do. Store an assistant message's tool calls whole, `argsError` included: a transcript the loop resumes from should carry the flag, though a malformed call the loop already answered is not run again without it. The new arguments are optional.
