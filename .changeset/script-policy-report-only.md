Every HTML response now sends `Content-Security-Policy-Report-Only` with a `script-src` that names each script the framework writes, so the browser reports any other inline script a page runs. 3.5.0 will enforce the same policy.

- A server-rendered page sends `script-src 'self' 'nonce-…' 'sha256-…' 'strict-dynamic'`: the hashes name the document's bootstrap script, its flush call and the build's import map, and the nonce the scripts React writes to reveal a streamed boundary. A page replayed from the HTML cache carries no nonce and lists the hash of each of those scripts instead; a page with more than 32 of them is rendered each time rather than stored. `akan start` adds `'unsafe-eval'` and runs its dev scripts under the nonce.
- The document's per-request values (route state, dictionary URL, import map key, API and WebSocket prefixes) and its Flight chunks are now `<script type="application/json">` blocks that the static bootstrap script reads, where they used to be script text. The bootstrap script is the first element of `<head>`, and the client entry module is added by that script once the document ends, where it used to be a `<script type="module">` tag.
- The CSR document, the system pages, Akan Studio, the gateway's status page and the OAuth error page send the header too, each naming its own script by hash. The OAuth error page now also carries the headers every other HTML page has (`Content-Security-Policy: frame-ancestors 'self'; base-uri 'self'`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`).
- `scriptHashes("sha256-…")` and `scriptNonce()` from `akanjs/client` let a `.head()` name its own inline script: by hash for a constant snippet, which keeps the page cacheable, or by the response's nonce, which makes the page dynamic.
- `AKAN_CONTENT_SECURITY_POLICY_SCRIPT_SRC` adds source expressions to every response's `script-src`, such as `'wasm-unsafe-eval'` for a page that compiles WebAssembly or the hash of a snippet every page carries.
- `AKAN_CONTENT_SECURITY_POLICY_REPORT_ONLY=off` drops the header, and any other value is sent in its place as written. `AKAN_CONTENT_SECURITY_POLICY_REPORT_URI` adds `report-uri` and `report-to` with a `Reporting-Endpoints` header. `AKAN_CONTENT_SECURITY_POLICY` works as before and does not change the report-only header.

**Upgrading.** Nothing breaks in 3.4: the header only reports. Load your pages with the browser console open. For each `[Report Only]` line about an inline script of your own, either call `scriptHashes()` in that page's or layout's `.head()` with the hash the line prints, or pass `nonce={scriptNonce()}` to the `<script>`; a `<script src>` written in JSX needs the nonce. Move an `onclick="…"` attribute or a `javascript:` URL into a component's handler. A page that compiles WebAssembly is reported as `wasm-eval`: set `AKAN_CONTENT_SECURITY_POLICY_SCRIPT_SRC="'wasm-unsafe-eval'"`. Code that read the document's inline scripts (`self.__RSC_PUSH__(…)` text, or a `<script type="module">` tag for the client entry) finds data blocks and no such tag. If a proxy or CDN in front of the app sets its own `Content-Security-Policy-Report-Only`, set `AKAN_CONTENT_SECURITY_POLICY_REPORT_ONLY=off` or let the app's header through.
