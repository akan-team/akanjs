An access token signed by `@libs/util` now lives one hour instead of seven days, and `@libs/shared` gains `session.cookieOnly`: with it on, a server-rendered web app holds its session in HttpOnly cookies alone.

- **One hour, one source.** `accessTokenSeconds` in `@libs/util/common` is the lifetime `signAccessToken` uses by default. The refresh token still lives 30 days, the session cookies keep their 30 day `Max-Age`, and an OAuth client's token still follows `oauth.accessTokenSeconds`.
- **Renewal.** A page still refreshes two minutes before the token expires and when its tab becomes visible again. New: `@libs/shared` registers `option.setSessionRefresh`, so a page load or RSC navigation that arrives with an expired access token is renewed from the request's refresh cookies before it renders. A user and an admin identity held together each come back on their own refresh cookie. An app's own `setSessionRefresh` wins over the lib's, and `setSessionRefresh(null)` turns it off.
- **`session.cookieOnly`** (`env.server.*`, off by default). Sign-in, SSO completion and refresh (`signinWithPassword`, `signinWithPhone`, `signinWithSso`, `exchangeSsoCode`, `activateUser`, `refreshJwt`, `signinAdmin`, `refreshAdminJwt` and the other answers built by `makeAccessTokenResponse`) answer a server-rendered page with the session and refresh cookies and a body of `{ jwt: "", expiresAt }`: no token and no `refreshToken` field. The page's calls, file uploads, agent stream and websocket authenticate by cookie, and the page sends no `Authorization` header.
- **Who still gets tokens in the body.** A caller that holds no session cookie and asks for them with the request header `x-akan-session-tokens: body`. The framework's `fetch` sends it to its own server from a native shell, a client-rendered app, a server (`fetch.clone`) and a test, and never from a server-rendered page. A page on an allowlisted origin other than the server's own counts as asking, so a native app released before this version keeps working. Such an answer sets no session cookie.
- **Framework.** `sessionTokenContract` in `akanjs/common` names the header. `setAuth()` with no token beside a session the server holds stops `fetch` from sending one and reconnects the socket so its handshake carries the cookie. `WsClient.connect({ fresh: true })` replaces an open socket.

**Upgrading.**

1. For everyone: access tokens expire after an hour. Nothing changes in an app that mounts `Auth.TokenRefresh` (or calls `refreshSession`) and uses the `@libs/shared` sign-in endpoints. Code that keeps an access token of its own, such as a script that signs in once and reuses the token for days, must now refresh it with `refreshJwt` / `refreshAdminJwt`, or sign in again. `getAccessTokenByAdmin` answers a one hour token too.
2. `RevokedSessions.accessTokenDays` is gone. `RevokedSessions.deniedSeconds` is how long a revoked session's tokens stay refused, and stays seven days.
3. Your own endpoint that answers with `makeAccessTokenResponse` or `makeAdminAccessTokenResponse` passes the request, `makeAccessTokenResponse(token, { req })` (`.with(Req)`). With `session.cookieOnly` on, an answer that names no request never carries tokens in its body.
4. To turn the option on, set `session: { cookieOnly: true }` in `env/env.server.<env>.ts`. Client code that reads `jwt` or `refreshToken` from a sign-in or refresh answer in a server-rendered page gets an empty string and no field: hand the answer to `setAuth` as the `@libs/shared` stores do, and read the signed-in account with `getAccount()` / `getSelf()`.
5. Do not turn it on yet if your web pages are served as the client-rendered view on the server's own host (`?csr=true`, `/__csr`) in a browser that also holds the session cookie, if a client of yours on another origin that is not in the allowlist reads body tokens with a hand-written HTTP call, or if page code needs the token itself, for example to put it in a URL or hand it to another service. Tabs opened before the deploy keep their session by cookie but lose their live subscriptions at their first refresh until they reload.
6. In 3.5.0 `session.cookieOnly` is on unless you set it to `false`.
