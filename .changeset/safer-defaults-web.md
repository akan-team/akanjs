Tighter defaults for the web client and the in-page agent. Every changed default below names the option that restores the old behaviour.

- **Write tools confirm by default.** An `st.tool` whose name starts with `remove`, `delete`, `create`, `update`, `upsert`, `submit`, `save`, `send` or `export` now shows the approval card unless it declares `confirm`. Before, only `remove*` did. This covers `submit<Model>` in `Model.EditModal` and `exportCsvOf<Model>` / `exportJsonOf<Model>` in `Data.ListContainer`. Opt out per tool with `{ confirm: false }`, which also drops the tool's confirm mark in the dock and the screen actions and its MCP `destructiveHint`, or app-wide with `AgentConfirm.set({ byName: (name) => name.startsWith("remove") })`.
- **A change right after a page read asks once.** A tool can declare `taint: "source"` (its result carries text the user did not write) or `taint: "exempt"` (it only moves the view). `readScreen`, `readState` and `viewImage` are sources, and `navigate`, `goBack` and the framework's view-only tools are exempt: tabs, dialogs, dropdowns, the side menu, the screen navigator, a list's view, sort, page size and page, and opening or closing a detail view. After a source call, the next call that changes something shows the approval card, even with `confirm: false`. A read (`settle: false`) and a card tool do not count as changes. The user's approval lifts the ask until the next source call. `st.tool(name, { taint })`, `useAgentTool(name, { taint })` and `ToolEntry.taint` declare it. Turn it off app-wide with `AgentConfirm.set({ afterScreenRead: false })`, or with `AgentSession` / `ToolRunner` `askAfterUntrusted: false`.
- **Page text reaches the model fenced as data.** A `taint: "source"` result or error is wrapped in a `<page-content …>` block. The block has a fresh boundary per call and a note that its contents are data, not instructions. The agent's system prompt, and the default prompt of the Anthropic and OpenAI-compatible adaptors, say the same.
- **`readScreen` withholds more.** It never reads the value of an input with `autocomplete` `one-time-code`, `current-password`, `new-password` or a card field (`cc-number`, `cc-csc`, `cc-exp*`). It also withholds any element marked `data-agent-private`. A private control prints only its kind and name, and a private region prints `[private: label]`, even when asked for by name. A private region is never a `highlight` or section target. Mark content `data-agent-private` to keep it from the agent.
- **The agent transcript belongs to one account.** A stored transcript, including one under an app-chosen `persist.key`, now records which account wrote it. It is neither restored nor overwritten while another account is signed in, and other accounts' transcripts under the app's default keys are removed. Default keys now include the account (`akan.agent.<app>.<account>[.<zone>]`), so transcripts stored before this change are removed, not restored; a `persist.key` of the app's own is kept, even one under `akan.agent.<app>`, unless it holds such a transcript. `Agent.Chat` and `Agent.Zone` reset a conversation they own when the signed-in account changes in this tab, or in another tab once this one is focused again. A session the app provides (`AgentProvider`, `SessionContext` or `Agent.Zone`'s `session`) is left to the app, and a `SessionHistory` passed as `persist` or attached with `Agent.History` keeps what it stored. `AgentSession.reset({ keepHistory: true })` empties a transcript without clearing its history.
- **The session token stays on the app's origin.** A `FetchClient` sends the token set with `setJwt` only to its own origin, over HTTP and WebSocket. `fetch.clone({ origin })` for another origin starts without it. Pass `clone({ origin, jwt })` to send one on purpose, over HTTP and WebSocket. A per-call `{ token }` covers that HTTP call only: the socket a call opens for its `FetchPolicy.origin` carries no token.
- **SSR web pages keep no token in `localStorage`.** `setAuth` on an SSR web page removes the stored copy, so the session cookie is the only place the token is stored. CSR and native clients still keep it in `secretStorage`. A web CSR boot with nothing stored now adopts the session cookie of an SSR page on the same origin.
- **Server-held sessions.** New `SessionCookie` (`akanjs/fetch`): `SessionCookie.issue(jwt, { maxAge })` returns the `Set-Cookie` values for an HttpOnly session cookie and a readable claims cookie beside it, and `SessionCookie.expire()` returns the sign-out values. While the claims cookie is present, the page never writes the session cookie itself, and `getAccount()` and form drafts read the account from the claims (`getSessionClaims()`). Nothing changes until a server sends these cookies.
- **`pathChange` goes only to known parents in production.** `router.postPathChange` posts to a same-origin parent frame, or to origins the app names with `router.setFrameParentOrigins([...])`. Local mode still posts to any parent. `router.setFrameParentOrigins("*")` restores the old target.
- **`l.rich` escapes its params.** Param values are HTML-escaped before interpolation, and a param named `br` no longer replaces the line break. Put markup in the dictionary text, not in a param.
- **Links in agent markdown.** `isSafeHref` drops tabs, newlines and leading control characters and spaces before it reads the scheme, as a browser does, so a disguised `javascript:` link is refused.
- **CSV export keeps formulas as text.** A text cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets a leading `'`. Numbers are written unchanged.
