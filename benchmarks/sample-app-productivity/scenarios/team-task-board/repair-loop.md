# Repair Loop Rules

The benchmark's default mode is `repair-loop`.

## Maximum Attempts

- First implementation prompt: 1 attempt.
- Repair prompts: at most 3 additional attempts.

## Allowed Repair Input

When build, lint, convention, or smoke verification fails, provide only:

- The command that failed.
- The checker name if the failure came from a convention check.
- The raw failure log.
- The failed acceptance criteria.
- The path to the build, lint, convention, start, or smoke log generated by the benchmark harness.

## Disallowed Repair Input

Do not provide:

- Human interpretation of the root cause.
- Stack-specific implementation hints.
- Suggested code snippets.
- Links or docs that were not equally provided to every stack.
- Extra product requirements.

## Stop Conditions

Stop when:

- Build, configured lint, configured convention check, and smoke test pass.
- The repair attempt limit is reached.
- The app cannot start due to dependency or environment failure.

Record failed runs. Do not hide them from the report.

## Cursor Report

After the final attempt, save token and timing metadata as `cursor-report.json` in the workspace. If an exact export is
not available, copy the stable shape from `schemas/cursor-report.example.json` and leave unavailable fields as `null`.
